# Changelog

## 0.0.1 (unreleased)
- Live captions, engine side (ADR-006): the session re-decodes the speech in progress (last 10 s, about every 0.7 s, Others by default, Me optional) and the app emits a transient `caption` event. Nothing is written or logged. Backs off when decoding is slow and switches itself off if it cannot keep up. The overlay's `set_captions` flags feed `Events::captions_wanted`.
- Fix: Download model no longer makes the voice activity pack the active model (it displaced Parakeet to `previous`); only transcription packs are activated.
- Fix: engine builds (the app and `sprkctl --features engine`) rejected the voice activity pack with `unknown engine 'sherpa-onnx/vad-silero'`, so Download model could not install it. Found by the real download test on the VM; the VAD engine is now in the supported list.
- Model download: packs can be published as parts (`sprkctl model index --split-mb 80 --parts-dir <dir>`), because the release host rejects uploads over about 100 MB. The index lists each part with its own checksum; the app joins them, checks the whole-pack checksum, then imports as usual.
- Model download (ADR-005): portable core (`sprk_models::remote`: index parsing with https and path checks, version comparison, download then checksum then the normal import) with fake-tested paths, a WinHTTP client in the app, Tauri commands `model_status`, `model_check_update`, `model_download` with `model-download` progress and `model-update` launch-check events, policy keys `ModelDownload`, `ModelUpdateCheck`, `ModelIndexUrl` (plus the model trust keys now parsed), `sprkctl model index`. The Settings pane button is for the redesign thread. CLAUDE.md rule 2 and SPEC amended.
- sprkctl: `model list` with no scope now shows every store the app reads (bundled next to the exe, machine, user) with a store column; `--scope user` now uses `%AppData%` like the app (it used `%LocalAppData%`, so user installs were invisible to the app).
- CI: the Linux job now runs on the Forgejo runner (it never had; it died in 3 s on a third-party Rust action the runner cannot fetch). Rust comes from rustup, the workflow moved to `.forgejo/workflows/ci.yml`, and it checks fmt, clippy (host plus both Windows targets), tests, terms and version alignment. The Windows and ARM jobs were removed (no such runners; Windows is checked by `winvm.sh`). Fixed the findings from newer clippy and removed unused dependencies.
- Notices: `scripts/gen-notices.py` regenerates the license summary and crate table and fails when a dependency has no license; run before each release. The Tauri shell's own dependency list still needs adding.
- M14 (policy): typed admin policy (`AppPolicy`) read from `HKLM` then `HKCU` `Software\Policies\SprkNotes` (read-only registry store, bad values ignored); the app uses it for the transcripts root, commit delay, filler removal, audio source detection and windows, exclusion patterns, call context, poll interval and 1:1 naming. UI lock indicators still to do.
- M14 (start): a panic on the session thread closes the transcript as `interrupted` (committed lines are already on disk) and reports to the UI; the app's panic hook prints only the source location, never the message.
- M13 (written, VM check pending): `scripts/release.ps1` (aligned x64 and arm64 builds, MSIs, MSIX bundle, portable zip with launcher, hashes, version alignment gate), WiX package, MSIX manifest template, `Install-SprkNotes.ps1`, `Install-SprkModel.ps1`, Intune notes, `SprkNotes.exe --version`.
- M12 (host wiring): the session host polls audio sources (every 250 ms) and call context (hysteresis, Teams titles only), writes `Audio source` and call mode event lines, closes activities at Pause and End, and only names the remote speaker in a confirmed 1:1 call. The Tauri `start_session` turns it on for Windows builds. Teams local API probe, media sessions and tab strips are still to do.
- M11 (logic + Windows): `SourcePoller` (300 ms audibility hold, -50 dBFS, ignorable sessions, exclusions before storage), title resolver chain (media session, tab, window title, app name) with browser suffix stripping; Windows window enumeration and WASAPI session metering with browser helper-process walk-up. UI Automation tab strips and media sessions are still to do.
- M8/M9 (Windows): classic Outlook calendar provider over COM late binding (read-only, silent when unavailable), Windows shell launcher for the handoff (open link, clipboard, reveal in Explorer, toasts). Verified to compile for both Windows targets; real Outlook check pending (docs/manual-checks.md).
- M5 (wiring): Tauri commands `start_session`, `pause_session`, `resume_session`, `end_session`, `rename_session`, `set_source` drive the session host; events `transcript-line` and `session-status`; model chosen through the resolver at Start (bundled, machine, user stores; the voice activity pack is found by engine string). Build with `--features engine` or `engine-shared`.
- Session host (portable): one thread owns capture, VAD, ASR, commit buffer and the crash-safe writer; UI side gets commands and `Events`. Rename during the session (user name wins), finalize on End or when the UI disappears, capture device events written as source events.
- M4 (portable core): echo plan by form factor (headset: dedupe only), NLMS software canceller with double-talk guard behind `EchoCanceller` (ADR-004). Windows AEC control and the hardware bleed test are pending.
- M2 (capture): `LiveCapture` follows default mic and render devices (device change, unplug, recovery events, failed-open keeps old stream) behind a `Backend` seam; cpal backend (WASAPI mic + loopback) in `sprk-audio` behind `cpal-backend`; `sprkctl capture-check` prints per-source counts and levels without storing audio.
