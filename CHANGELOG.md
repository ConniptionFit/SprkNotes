# Changelog

## 0.0.1 (unreleased)
- Ask Sprk, in the app (ADR-009; off by default, all extras off until chosen): Settings section (on/off, size, a switch per feature), an Ask button and panel (What did I miss?, Action items, a question box, with timestamps for the lines each answer came from), and a "Suggest a title" button for an unnamed session. Optional extras, each its own switch: agenda check, my commitments, pin a moment, parking lot, explain this, say it again short, next-meeting prep. New policy key `AssistantFeatures` (allow-list). Everything runs on this PC; question history is in memory only. The release script now builds and ships the `sprk-assistant` helper for both architectures. New Gemma 4 prompt format.
- Assistant features, engine side (ADR-009, not in the UI yet): cited recap of the last N minutes (piece by piece for long windows, then merged), action items with owner and due only when stated (deduplicated across pieces), and a question answerer that finds the relevant lines with BM25 search and answers from them or says "not stated". Every claim is checked in plain code: citations must be lines the model was shown, and numbers, weekdays, months and names in a claim must appear in the cited lines or the participant list; anything that fails is dropped instead of shown.
- Assistant tooling: `sprkctl model ... --kind assistant` installs and lists assistant packs in their own folder (`assistant-models`); a transcription store refuses an assistant pack with a plain reason. `sprk-assistant-bench` (load time, prompt speed, time to first text, generation speed, peak memory, optional background load) for the laptop benchmark; `scripts/make-assistant-pack-folder.py` turns a GGUF into a pack folder.
- Assistant engine (ADR-009, still off and not wired to the UI): the llama.cpp helper (`crates/sprk-assistant-llama`, CPU, built on its own because it compiles C++) behind the same pipe protocol, with shared stream helpers (whole UTF-8 characters, stop strings across pieces) and `effective` / `status` logic that merges policy with the user's choice (off by default, Light default, policy locks). Tested through the real binary against a tiny random-weight model made by `scripts/make-test-assistant-model.py` (no download); real models and real timings still need the laptops.
- Assistant helper process (ADR-009): the `sprk-assistant` helper binary and `RemoteEngine`, the app-side client that runs it at below-normal priority and speaks the pipe protocol. Hold, resume and cancel follow the caller's run control while a request runs; a dead helper is a plain failure, never a hang. No real engine is compiled in yet, so Load answers `load_failed` until the llama.cpp adapter lands.
- Assistant foundation (ADR-009, ADR-010; off by default, nothing visible yet): new `sprk-assistant` crate (engine trait with a scripted fake, line-numbered transcript view, app-owned prompt formats, dynamic note titles with cleaning and a grounding check, the resource governor for tier choice, lag yield, idle unload and thread caps, the helper pipe protocol); `model.json` gains an optional `kind` (`transcription` default, or `assistant`) and an `assistant` section, and a store accepts one kind; policy keys `AssistantEnabled`, `AssistantTier`, `AssistantPinnedModel`, `AssistantIdleUnloadMinutes`, `AssistantMaxThreads`, `AssistantSaveOutputs`, `AssistantBackground`. No model runs yet: the llama.cpp helper and the laptop benchmark come next.
- Open items from the overnight sweep: speaker-bleed removal also catches a mic line that is a piece of a longer remote line or spans two (containment test, 4 words or more, 80% in order, in addition to whole-line similarity); Linux default input and output switches are now noticed (the device name was constant), so a Source changed line is written; resume restarts the capture streams so audio buffered during the pause is not stamped as new (Others lines were about 2 s late); live captions lower a title-cased run of three or more words so they match the saved line; Start falls back to ~/Documents when no Documents folder is configured. Still needs a real-hardware check on Linux for the device switch and the resume timing.
- Overnight sweep 2 fixes: the overlay clock counted timer ticks and ran at half speed in the throttled overlay window (it now follows real time); a source switched off and on again stamped its later lines early by the length of the gap (about 30 s after a 30 s Me-off), so lines came out of order. Turning a source off now also finishes what it was hearing. Hour-long runs (non-stop speech, conversation, speaker bleed, 75-minute soak) read back 97 to 99% of words with no ordering errors apart from that bug, and memory stayed flat.
- Main window polish: the bottom bar is icon-only with short tooltips (Library, Settings as a gear, Summarize) and no SprkNotes mark; the status light shows only while transcribing or paused; wide windows use the width (fluid side padding, name and sound sources share one line) instead of a centered column. Throwback Mode keeps the normal text colors (it set a dark text color that was unreadable on dark), moved to a new Misc panel at the bottom of Settings with the line "Get a blast from the past."
- Single instance: starting SprkNotes again (desktop or Start menu shortcut, Linux launcher, a second exe launch) no longer opens a second copy. The new launch exits and the running one comes forward, restored from the tray or from minimized, the same as a tray click (`tauri-plugin-single-instance`).
- Overnight test fixes (PRs 55 to 60). Non-stop speech is cut and committed steadily (the voice detector only honored its maximum length at a pause, so lines stalled for a minute and End then spent over a minute decoding). Lines are written in time order when both sources talk at once (about 30 backwards steps in a 105-line two-source run before). 1 s of audio is kept before detected speech (never reaching into the previous utterance) so a sentence's first words are not lost, including after a quiet spell (PRs 59 and 60). Crash recovery (SPEC 6.4): at launch, transcripts a crash left in progress are offered with Open and Mark finished. Errors are shown instead of swallowed: a failed Start, a line that could not be saved, a transcript that could not be closed. Linux install notes now build the UI before the binary.
- Live captions, lock-in (ADR-008): sentences lock in as they finish (or after 1.5 s, or a pause) instead of one grey block growing for minutes; locked text is normal color and is only fixed silently later by the finished line. Hypotheses are aligned to locked text so the sliding window no longer unsettles the line. New Settings choice "Live text delay" (Fast, Steady, Smoothest) holds new words a moment so fewer change on screen, text types out at an even pace, and only the last word or two are soft (no underline). The transcript fills from the bottom, new rows push older ones up. Fix: the transcript stopped following new lines after a while and stuck in place; follow now turns off only when you scroll up, and the end stays in view as text grows.
- Docs audit: new [Features and usage](docs/features.md) page with screenshots for every feature; README, user guide and install brought up to date (Close hides to the tray, tray click restores, Linux install script and desktop entry, End no longer hangs). New screenshots: named session with a source off, overlay paused. `scripts/screenshots.mjs` now also covers these.
- Docs: screenshots regenerated for the new brand (PR 48), with new ones for Library, Summarize (choose an app, no app found) and Throwback Mode; user guide and README describe the brand, Throwback Mode, Library and Summarize. Throwback screenshots were taken on Linux without Segoe UI, so the font differs from Windows.
- Library and Summarize now work (both were disabled placeholders). Library: list, search names and full text, read, View in folder, Export (docx, txt, json). Summarize: hands the transcript to the Claude or Copilot desktop app, picking the one installed, asking when both are, and copying the prompt and showing the file when neither is (SPEC 9.0). New `sprk_transcript::library`, `sprk_handoff::detect`, a Linux launcher (`xdg-open`, wl-copy/xclip/xsel), policy keys `CopilotTarget` and `PromptTemplatePath`. The Windows Copilot link (`ms-officeapp:`) still needs a check on a real PC. Not yet: folders, rename and delete in the Library.
- Docs refresh: user guide, README, install, architecture and admin guide brought in line with main (redesigned window, Settings, overlay and captions, live line, tray, model download in parts, native Linux). New screenshots in light and dark for every state (main window, Settings and model states, overlay, caption drawer including flipped and large text, tray icons), generated by `scripts/screenshots.mjs` from the UI's browser mock so they stay synthetic. Screenshots will need re-running after the rebrand lands. Known gap documented: Close does not yet hide to the tray.
- Live line in the transcript window (PR 45): the newest words of the speech in progress appear word by word as a final row, Others by default (Me follows the captions setting); a Settings switch and text size buttons. Never saved.
- Native Linux support (PR 39): model download without WinHTTP, system audio from the default output's monitor via `parec` (PipeWire or PulseAudio), drag and drop off, XWayland by default for the overlay (`SPRKNOTES_WAYLAND=1` opts out), the tray is optional when no tray host exists.
- UI redesign: status light instead of a status word, plain-language labels, Settings with transcription model, appearance and captions sections, first-run model download card, tray icon with state and menu, overlay (concept C: orb plus caption bar).
- Overlay caption drawer polish: slightly translucent (86%) so it stays readable over any window; resizable with a hover-only corner handle (drag or arrow keys); magnifier minus and plus buttons for text size; drawer size and text size are remembered across runs (and the pill position as before). When the pill rests in the lower half of the screen the drawer flips above it, the pill stays put, and the handle moves to the upper-right corner. The hover-only buttons now hide about 0.9 s after the pointer leaves or the overlay loses focus (a mouse click used to leave a button focused and pin them open).
- Live captions, engine side (ADR-006): the session re-decodes the speech in progress (last 10 s, about every 0.7 s, Others by default, Me optional) and the app emits a transient `caption` event. Nothing is written or logged. Backs off when decoding is slow and switches itself off if it cannot keep up. The overlay's `set_captions` flags feed `Events::captions_wanted`.
- Fix: Download model no longer makes the voice activity pack the active model (it displaced Parakeet to `previous`); only transcription packs are activated.
- Fix: engine builds (the app and `sprkctl --features engine`) rejected the voice activity pack with `unknown engine 'sherpa-onnx/vad-silero'`, so Download model could not install it. Found by the real download test on the VM; the VAD engine is now in the supported list.
- Model download: packs can be published as parts (`sprkctl model index --split-mb 80 --parts-dir <dir>`), because the release host rejects uploads over about 100 MB. The index lists each part with its own checksum; the app joins them, checks the whole-pack checksum, then imports as usual.
- Model download (ADR-005): portable core (`sprk_models::remote`: index parsing with https and path checks, version comparison, download then checksum then the normal import) with fake-tested paths, a WinHTTP client in the app, Tauri commands `model_status`, `model_check_update`, `model_download` with `model-download` progress and `model-update` launch-check events, policy keys `ModelDownload`, `ModelUpdateCheck`, `ModelIndexUrl` (plus the model trust keys now parsed), `sprkctl model index`.
