# ADR-015: SprkNotes for Android (Samsung phones)

Status: **proposed** (2026-11-25). John picked the look (Decision 6); accepted when this merges. No Android build is published without his yes.
Related: ADR-001 (stack), ADR-003 (default model), ADR-005 (model download), ADR-014 (streams).

## Context
Lifespark mostly uses Samsung Galaxy phones. John wants an Android SprkNotes in this repo, Rust-based and as close to
the Windows app as possible, that tunes itself to the phone's AI hardware without a bloated installer, and he wants
future desktop work to port to it easily. Hard rules 1 to 15 in CLAUDE.md apply unchanged: on-device only, no network
except model packs and app updates, no audio on disk, "transcribing" not "recording".

## Decision 1: one app, two platforms (Tauri v2 mobile)
Use Tauri v2's Android target from the **same** `app/src-tauri` crate and the **same** Svelte UI. No second app, no
Kotlin rewrite, no fork of TrailMix.

```
crates/                 portable Rust, no Tauri (unchanged rule). Shared by Windows and Android.
  sprk-audio            + `android` capture backend (cpal/AAudio, mic only) behind live::Backend
  sprk-asr              + `tune` module: hardware probe and engine/model choice (Decision 2)
  sprk-core   (new)     session control, settings, library and model logic moved out of
                        app/src-tauri/src/main.rs so both shells call one API
app/src-tauri
  src/lib.rs  (new)     #[cfg_attr(mobile, tauri::mobile_entry_point)] run(); main.rs calls it on desktop
  src/desktop/          tray, mini overlay, hotkey, updater, mic_watch, Outlook/Teams: cfg(desktop)
  src/mobile/           foreground service, notification controls, permissions: cfg(mobile)
  gen/android/          generated by `tauri android init`, committed
app/ui/src
  lib/                  shared components (LivePane, Library, Settings, SourceButton, waveform...)
  lib/mobile/           phone-only layout pieces (bottom bar, sheet menus); same tokens, same Outfit font
```

**Rules that keep it portable from now on**
1. New behavior goes in a `crates/` crate first; `app/src-tauri` only wires commands and platform pieces.
2. New UI is a component in `lib/` that takes props and does not assume a window size or a mouse (44 px touch targets,
   no hover-only actions; hover text also appears on long-press).
3. A desktop-only feature is behind `cfg(desktop)` in Rust and a `platform.desktop` flag in the UI, never an `if windows`
   scattered through shared code.
4. Settings and admin policy keys stay one list (SPEC 10.2b); each key says which platforms read it.

**Why not Kotlin (TrailMix fork) or Flutter:** both mean a second UI and a second settings, library and transcript
implementation to keep in step. Tauri mobile reuses the Rust pipeline, transcript writer, model packs and Svelte UI.
Risk: Tauri mobile is younger than Tauri desktop; Android services and audio need a small Kotlin plugin (below).

## Decision 2: tune to the phone at runtime, CPU first
**Feasible: yes.** Detecting the hardware is cheap and needs no extra libraries:
- Android: `Build.SOC_MANUFACTURER` and `Build.SOC_MODEL` (Android 12+), total RAM, big-core count, CPU features from
  `/proc/cpuinfo` (`asimddp`, `i8mm`).
- Then a **3-second self-check** on first run and after an app or model update: decode a bundled synthetic clip and
  measure the real-time factor. The numbers decide, not a table of chip names that goes stale.
- The result picks: model tier, decode threads (big cores only), live caption cadence. Stored per device; Settings shows
  "Tuned for this phone" with a Re-check button. The same `tune` module serves the desktop (Snapdragon X vs Intel).

**What the NPU options look like today (read 2026-11-25)**

| Path | Works for us now? | Size cost |
|---|---|---|
| CPU int8 via sherpa-onnx + ONNX Runtime (today's engine) | Yes, every phone | onnxruntime about 15 MB per ABI |
| Qualcomm NPU (QNN/HTP) via sherpa-onnx or ORT QNN EP | Not for English Parakeet. Models must be precompiled **per chip** (SM8550, SM8650...), have a fixed input window, and the published ones are Chinese/multilingual families; ORT ships QNN prebuilt for Windows only | QNN libs about 12 MB, plus 71 MB if compiled on device, plus a 72 to 351 MB model per chip |
| Samsung Exynos NPU | No open route we can rely on | n/a |
| NNAPI | Deprecated in Android 15 | n/a |
| GPU (Vulkan/OpenCL) | Possible later via a whisper.cpp engine; unmeasured for our models | adds a second engine |

So the app **detects** NPU, GPU and CPU features but **uses the CPU path** in v1. An NPU adapter can be added later as
an optional, separately downloaded "accelerator pack" behind the `Engine` trait (rule 15, its own ADR), only if pilot
phones miss the speed gates. Nothing in the main install grows for it.

## Decision 3: keep the install small
- **arm64-v8a only** (`tauri android build --apk --target aarch64`). Every current Galaxy phone is arm64; dropping
  armv7/x86 cuts native code by about three quarters.
- **Models are not bundled.** First run downloads the pack (ADR-005, same checksums and policy switch; the download
  code now lives in `sprk-core::download` and is shared by the desktop and the phone) or IT pushes it
  with the MDM; a pack file can also be imported. One model family, two tiers:
  - **Full:** Parakeet TDT 0.6B v2 int8 (about 460 MB download, 631 MB installed, about 1.1 GB RAM) for phones with
    8 GB RAM or more that pass the self-check.
  - **Light:** Whisper base.en int8 (154 MB installed, under 0.5 GB RAM) for everything else.
- **Sizes:** measured 2026-11-25 in CI, the unsigned arm64 release APK of the app shell (Tauri, web UI, shared crates,
  no speech engine yet) is 13.5 MB. The engine is wired in since 2026-11-27: only `libsherpa-onnx-c-api.so` (4.3 MB)
  and `libonnxruntime.so` (22.2 MB) go into `jniLibs/arm64-v8a`. Measured 2026-11-27 in CI, the unsigned arm64
  release APK is 45.5 MB: the app library is 17.3 MB, and Android's default packaging stores native libraries
  uncompressed so the phone loads them in place with no copy at install. Compressing them would shrink the APK to
  roughly 20 MB but unpack about 44 MB at install, so the installed size would not drop. The Android workflow prints
  the size and the APK's native libraries on every build.
  `scripts/fetch-sherpa.sh android-arm64` fetches just those two and the build is pointed at them with
  `SHERPA_ONNX_LIB_DIR`; without it the whole sherpa-onnx Android archive (JNI and C++ wrappers too) would be copied. A universal 4-ABI APK would be about 90 to 120 MB;
  bundling Parakeet would push it past 500 MB.

## Decision 4: Me and Others on a phone
Android does not let an app capture another app's call audio (voice-call capture is reserved for system apps, and
playback capture excludes voice communication). So a phone has **one** source: the microphone (built-in, wired or
Bluetooth headset).
- The source button reads **Mic** with the same device menu; there is no computer-sound button.
- **No speaker labels on phones in v1** (John, 2026-11-25). With one mic and no second stream the app cannot
  tell people apart reliably, so lines carry a time and no name: not Me, not Others, not Speaker 1. This is the
  mobile reading of rule 13: when the app cannot know who spoke, it says nothing rather than guess. Transcript
  files from a phone leave the speaker field empty.
- **Person 1, 2 later, only if accurate.** On-device diarization exists (sherpa-onnx ships it for Android), but the
  best open models still misattribute about 11 to 20% of speech on benchmark audio, and a phone on a table with
  crosstalk will do worse. It is built as a hidden test, measured on real Galaxy audio, and turned on only when John
  approves the numbers. An opt-in voice sample so the owner's lines read Me needs its own ADR (voiceprints are
  biometric data, kept on the phone only).
- Echo removal and bleed rules are skipped on mobile (there is no second stream to subtract).

## Decision 5: Android specifics
- A foreground service with a persistent notification (Pause, End) keeps transcribing with the screen off; Android
  requires it and it is the honest signal that the mic is in use.
- Transcripts live in app storage, exported or shared only by the user (share sheet). No cloud folder by default.
- Distribution: private, not the public Play Store. Managed Google Play private apps or the MDM's own app push.
  Whether NinjaOne can push a private APK to Samsung phones is still unconfirmed; Knox/managed Play is the fallback.
- App updates use the same signed manifest idea as ADR-011 only where the MDM does not handle updates.

## Decision 6: the look (John's picks, 2026-11-25)
Picked from four interactive mock-ups (A desktop twin, B bottom tabs, C control dock, D conversation):
- **Layout D, conversation:** the transcript reads as message bubbles, newest at the bottom, with a slim bottom bar
  holding the Mic button and device menu, the waveform, the timer, End and a round Start / Pause button. Library and
  Settings sit behind icons in the top bar. Same Outfit font, palette and icons as the desktop app.
- **Dark theme by default** on phones (System and Light stay in Settings).
- **Sound meter matches the desktop exactly:** the same small meter inside the Mic button (shared `waveform.ts`),
  flat when there is no sound. Line wave only (one smooth stroke that swells with the voice), with no setting; Nine
  bars and Rolling bars are retired on both apps (John, 2026-11-25). No large or scrolling waveform strip: the screen
  moves as little as possible (John, 2026-11-25).
- **Settings uses the desktop gear icon**, not a sun (a sun reads as theme or brightness) (John, 2026-11-25).
- **No speaker labels** (Decision 4).

## Consequences
- Moving session logic into `sprk-core` touches `main.rs`; done in small PRs with the Windows build green each time.
- CI lints the whole workspace for `aarch64-linux-android` and builds an arm64 debug APK (`android.yml`).
  `gen/android` is committed, because it carries the microphone permission and the first-start mic prompt
  (`MainActivity.kt`); regenerate it only by hand and keep those two. No release or signed APK is published without
  John's yes.
- Not on phones in v1: tray, pop-out overlay, keyboard shortcut, Outlook/Teams naming, offer-to-start (Android hides
  other apps' mic use), Summarize hand-off (later via the share sheet).

## Open items
1. Speed and RAM of both tiers on a real Galaxy (which models does Lifespark hand out?).
2. NinjaOne private APK support, or managed Google Play.
3. Accuracy bar for turning on Person 1, 2 (John decides on measured numbers).
4. The model download runs inside the app, so it stops if Android closes SprkNotes in the background. A foreground
   service with a progress notification would let it finish with the screen off.
